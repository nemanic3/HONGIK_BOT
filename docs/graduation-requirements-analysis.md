# 홍익대학교 컴퓨터공학과 졸업요건 분석 및 확장 설계

## 0. 범위·출처·판정 한계

대상은 프로젝트 루트의 `(20260211)2026 교과과정책자 합본(안)_f1.pdf`다. 도구로 확인한 PDF 페이지 수는 **237**이며 사용자 설명의 236과 다르다. 이 보고서의 `PDF n / 인쇄 m`은 각각 파일 내 1-based 위치와 원문 푸터의 쪽수다. 공과대학 상세 교과표의 인쇄 쪽수는 `공-10` 같은 별도 체계다. PDF 1은 표지, 2는 목차다.[1]

파일명·메타데이터 제목에 `(안)`이 있으므로 **대학이 공표한 최종본인지, 정오표가 반영됐는지는 검증 필요**다. 아래는 제공 문서의 명시 기준을 추출한 것이며, 학교가 확인한 운영 판정으로 승격하지 않았다. SHA-256: `9d96c675c8df7d3f3a75971da582975e624dfda33a10f194774942216a17e5a5`.[1]

분석 시 기존 DB는 읽기 전용으로 열었다. 원본 DB에 마이그레이션·요건 변경·사용자 삭제를 하지 않았다. 비교 대상은 `GraduationRequirement(id=1, major=컴퓨터공학과, year=2025)`다.[2]

표의 `—`는 **해당 표에 별도 명시가 없음**이다. 면제·0학점·불필요라는 뜻으로 사용하지 않는다. 모호한 조건, 인증 이수내규에 위임된 조건, 수강 당시 교과과정·복학 이력이 필요한 조건은 **검증 필요**로 남긴다.

## 1. 교과과정 적용원칙과 경과조치

입학연도는 총학점/과정 기준을 고르는 중요한 키지만, 필수과목 목록 전체를 고정하는 유일한 키는 아니다. 원문은 **재학하는 학년·학기의 교과과정**과 **별도 경과조치 우선**을 함께 명시한다. `admission_year`, `academic_year`, 현재 학년, 복학·학기 상치 이력을 구분해야 한다. PDF 3–4 / 인쇄 1–2.[1]

### MSC의 결정적 연도 경계

- **2024 이후:** 수학·과학 합계 **17** + 지정 전산 **6**, MSC 총 **23**. 컴공 비인증에는 대학물리·대학화학 별도 필수 요건 없이 수학·과학 합계가 17 이상이면 인정. PDF 10 / 인쇄 8.[1]

### 2003학년도 이전

인증 운영대상 학년과 동일하면 희망에 따라 인증 신청·동일 과목 소급인정 가능하며 졸업학점은 인증 이수내규에 따른다. 동일하지 않으면 인증 신청 불가, 교양필수·계열선수·전공35를 포함한 총140 기준이다. 학생별 운영대상 학년과 이력 없이는 인증/비인증 최종 규칙을 선택할 수 없다. **개별 검증 필요**다. PDF 16 / 인쇄 14.[1]

현재 규칙 파일은 제공 문서의 범위를 2026학년도까지 명시적으로 선택하고, 2027 이후를 자동 생성하지 않는다. 2003 이전에는 선택 가능한 검증필요 정책을 반환하지만 계산값을 임의 채우지 않는다.

## 4. 교양·영어·SW·논문 세부 조건

### 4.1 교양 영역

2016 이후는 기초교양6 및 일반/핵심교양 **7영역 중6영역에서 각각1과목 이상**, 그중 **예술과 디자인·제2외국어와 한문 반드시 포함**이다. 단순히 아무6영역이면 충족이라고 판정하면 틀린다. 영역별 동일한 요구학점을 임의 배분하지 않는다. PDF 5–6 / 인쇄 3–4; PDF 10–15 / 인쇄 8–13.[1]

2022 이후 영역은 언어와 철학 / 사회와 경제 / 역사와 문화 / 예술과 디자인 / 제2외국어와 한문 / 법과 생활 / 공학의 이해다. 일반교양과 전문교양 이름은 학과에 따른 역할을 구분해야 한다. PDF 49 / 인쇄 47.[1]

2004–2015는 핵심6·7·8 각각1과목, 일반1–5 중4영역 각각1과목이다. 2004–2013과2014–2015의 영역명도 다르다. 이를 현대7영역 목록으로 대체하지 않는다. PDF 46–47 / 인쇄 44–45; PDF 7 / 인쇄 5; PDF 15–16 / 인쇄 13–14.[1]

**전문교양23과 기초6+영역6개**는 함께 보존한다. 영역에2학점 CTO특강 같은 과목도 있어 모든 영역을3학점으로 고정하면 안 된다. 기존 코드의 “드볼17+2학점 영역이면 예외충족”을 제공 문서의 독립 졸업규칙으로 확인하지 못했다. 별도 공식 근거가 확보되기 전 **검증 필요**다. PDF 49 / 인쇄 47; PDF 5 / 인쇄 3.[1]

특성화는 컴공에 **디자인씽킹 또는 창업과실용법률 중1과목(3학점)**이다. 공과대학의 **컴퓨팅사고 수강불가**를 확인했다. PDF 34 / 인쇄 32; PDF 10 / 인쇄 8.[1]

### 4.3 SW/데이터활용역량인증

2022 입학생부터 필수이며 기본은 소양·기초·심화 각1과목 총9학점이다. **상위 모듈이 하위 모듈 요건을 충족**한다. 원문은 기초2+심화1, 심화3과목도 인정하는 예를 명시한다. **서로 다른 이수과목 세 슬롯 배정**과 총학점 조건을 함께 검사해야 한다. 총SW학점9라는 단일 합계만으로는 불충분하다. PDF 29 / 인쇄 27.[1]

공학계열에는 학과별대체인정과목을 별도로 정하지 않고, 다른 학과의 학과별대체인정과목을 이수해도 인증과목으로 인정하지 않는다. 반면 **전문대체인정**인 MSC 전산 및 지정 컴퓨터SW 전공과목은 **심화 모듈**을 대체한다. 두 대체 제도를 혼동하지 않는다. PDF 29–30 / 인쇄 27–28.[1]

## 7. 검증 필요 목록

1. `(안)` 파일의 공식 최종본·공표일·정오표.
2. 인증 내규: 영어·설계 최소학점·선후수 체계·예외·종합설계 지정.
3. 논문 합격 방식/대체 증빙, 영어 성적별 지정 및 면제.
4. 구학번 필수과목 적용: 재학 학년·학기, 휴복학, 폐지·선택 변경 경과조치.
5. 2004–2019 비인증 MSC의18하한과 과학 지정과목 병행 인정 사례.
6. 성적·P/F·재수강·중복취득·교류/편입/다전공 학점 배분과 교양상한 산입범위.
7. 컴공3학년 표의 의사소통8영역 표기를2016이후 학생에게 적용할지 여부. 현행1–7영역 체계에 임의 추가하지 않음.
8. 예전 학수번호·학점 변경 이력, 코드 같고 과목명 다른 경우의 동일성.
9. SW 전문대체 범위와 학교 시스템 실제 인증기록의 일치 확인.

항목1–9가 해결되지 않은 학생에게 **졸업가능/인증완료 확정 문구를 출력하지 않는다**. 상세 조건의 충족·부족은 근거가 확보된 범위에서만 안내하고, 전체 상태는 검증필요일 수 있다. 주요 한계 근거: PDF3–7 / 인쇄1–5; PDF29 / 인쇄27; PDF54 / 인쇄52; PDF99 / 공-11.[1]

## 8. 확장 데이터 구조 및 구현 방향

### 분리할 엔티티

- `RequirementRuleSet`: campus + canonical major + admission_year 범위 + accreditation_track + curriculum_year + version. `source_document`, SHA-256, 페이지 근거, `source_verified`, 선언적 조건 데이터.
- `CourseIdentity`: 학수번호 문자열, 명칭 이력, 취득 당시 학점/이수구분. 과목 이름만으로 성급히 동일시하지 않음.
- `CourseRelation`: rename_same / abolished_replacement_required / abolished_replacement_optional / same_replacement 등 의미 구분, 시작 학기와 대상 학생 조건, 근거 페이지.
- `CourseRecognition`: 학과·입학연도·수강연도별 MSC 분야·전공·교양 영역·SW 모듈 역할. 실제 이수 1건의 총학점은1회만 집계.
- `StudentContext`: admission_year, track, 현재 학년, 수강연도/학기, 휴복학·편입·전과 이력. 미입력은 자동추론하지 않음.
- `ExternalEvidence`: 논문/설계/영어/인증 최종통과 등 성적표 밖 증빙; 학교 확인 없이는 사용자 주장만으로 완료 확정하지 않음.

### 조건 타입

`credit_minimum`, `credit_cap`, `all_of`, `any_of`, `at_least_n_groups`, `area_coverage_with_mandatory`, `module_slots_with_upper_substitution`, `effective_period`, `review_required`를 분리한다. 각 조건에 원문 페이지와 적용범위를 저장한다. 엔진 결과는 `met / not_met / needs_verification`으로 내보내고, 모르는 규칙을0이나충족으로 처리하지 않는다.

### 현재 반영된 기반

- 기존 GraduationRequirement를 삭제·덮어쓰지 않는 별도 `RequirementRuleSet` 모델과 추가 마이그레이션.
- 사용자 인증과정은 `accredited / non_accredited / 미선택`이며 학번에서 자동추론하지 않음.
- `analysis/data/hongik_cs_2026.json`: 제공 PDF 추출 규칙·과목 카탈로그. 모두 `source_verified=false`. 페이지 근거 없는 대학 수치 생성 없음.
- `analysis/engine.py`: 소수학점 보존, 중복·재수강 검증필요, 상위→하위 SW 슬롯, 필수영역 포함, 근거 메타데이터.
- `GET /api/analysis/report/?transcript_id=...`: 로그인 사용자 소유 성적표를 **사용자 확정 후** 같은 규칙으로 분석. 상세·종합·학기표에 하나의 응답 사용.
- `load_curriculum_rules`: 기본은 읽기 전용 검증; `--apply` 명시 시 새 버전 등록. 기존 수치 자동 변경 없음.

주의: 이는 규칙 엔진의 **검증 가능한 범위 구현**이다. `CourseRelation`·복학 이력·학교 증빙 자동 처리와 모든 기존 개별 API의 정책 통합까지 완성됐다는 뜻은 아니다. 기존 레거시 API는 호환용으로 남기고 새 대시보드는 통합 엔진을 사용한다.

## 9. 단계별 개발·테스트 계획

### 2단계: 근거 규칙/엔진

1. 페이지 근거 추출, 원문 표 병합셀 시각 검증, 인증/비인증·연도 경계 분리.
2. 기존DB와 별도 버전형 규칙 모델, 겹치는 연도·버전 조회는 모호성 오류로 처리.
3. 총학점/상한/분야·지정과목/영역/SW 모듈의 선언적 평가.
4. 모르는 성적·분류·중복·재수강·내규는 검증필요로 출력.
5. 확정된 성적표와 정책 버전을 묶는 통합 API, 소유권 검사.

### 3단계: 사용자 흐름

업로드 PDF/JPG/PNG 제한 → OCR 원본보존/초안 → 사용자 행별 수정·확정 → 동일 transcript_id 분석 → 대시보드 학점·영역·학기 필터. OCR 실패도 원본과 오류 안내를 남기고 수동검수로 복구할 수 있게 한다. 고정 타이머 이동, 더미 수강목록, 132/50 하드코딩을 제거한다.

### 운영 전 검증

공식 최종본/내규 승인, 실제 홍익 성적표의 익명화 동의 샘플로 OCR 정확도 평가, 휴복학·편입/복수전공 사례 검증, 사용자 증빙 흐름, 자격증명/추적DB 정리, 인증·소유권·업로드 보안, queue/worker 장애 복구, 운영 DB 적용 별도 승인, 외부 배포 별도 승인.

## 10. 구현 검증과 실제 DB 적용 범위

전체 백엔드 자동화 테스트112개와 프론트 테스트34개, Django check·migration drift 검사, 프론트 typecheck·production build가 통과했다. 규칙 import는 기본 dry-run으로17개 미검증 초안 정책을 검증했고 원본 DB에는 쓰지 않았다. 실제 HTTP 업로드→확정→통합 분석은 새 사설 DB의 합성 데이터로 검증했다. 영어·한국어 합성 이미지의 로컬 Vision 인식도 확인했지만 실학생 성적표 정확도나 학교의 최종 졸업승인을 의미하지 않는다.

원본 DB·제공 PDF 해시는 작업 전과 같고, 추가 마이그레이션은 사본에서만 적용·보존 검증했다. 공식 최종본·인증 내규·개인별 경과조치가 미확인인 조건은 계속 **검증 필요**다. 기능별 변경, 명령별 결과, 독립 리뷰 및 운영 한계는 `FINAL_VERIFICATION.md`를 함께 확인한다.

원본 PDF와 DB는 이번 커밋에서 제외한다. 아래 출처는 개인 기기 경로가 아닌 프로젝트 기준 로컬 참조이며, GitHub에 원문·DB가 공개되어 있다는 뜻이 아니다.
